# Grant Arkhyz

Один готовый гостевой дом в Архызе. Студия и большой номер сдаются отдельно. Новая публичная страница ведёт к актуальному объявлению Avito и не собирает персональные данные.

## Просмотр и проверка

Node.js 22+:

```sh
npm ci
npm test
npm run build:public
npm start
```

Открыть http://localhost:3000. Для обычного статического хостинга загружать **только содержимое `dist/`** после `npm run build:public`. Там нет админки, серверных файлов, базы, старых форм и визуализаций. `/`, `/index.html`, `/start-sales.html` показывают новую страницу.

## Администрирование прежних заявок

Не нужно для публичного статического сайта. Старый интерфейс оставлен для доступа к прежним данным после отдельного безопасного развёртывания. Публичная форма закрыта с ответом 410; новая страница направляет на Avito.

Переменные окружения сервера:

- `ADMIN_USERNAME`, `ADMIN_PASSWORD`: обязательны, значений по умолчанию нет. При отсутствии только административные маршруты возвращают 503; сайт открыт.
- `ADMIN_ORIGIN`: точный HTTPS origin админки, например `https://admin.example.ru`, без завершающего `/`; нужен для операций изменения.
- `DATABASE_URL`: существующая PostgreSQL; не записывать в репозиторий.
- `PGSSLMODE=require`: TLS с проверкой сертификата для удалённой PostgreSQL. Доверенный сертификат провайдера при необходимости задавать через `NODE_EXTRA_CA_CERTS`; не выключать проверку.
- `PORT`, `HOST`: адрес прослушивания. Для отдельной админки за обратным прокси — `HOST=127.0.0.1`.

Внешний доступ к админке разрешать только через HTTPS и дополнительный шлюз с MFA/IP-ограничением и ограничением попыток входа. Basic Auth приложения — дополнительный слой, а не полноценная система пользователей. Публичный статический хост не должен проксировать `/api` и `/admin.html`.
