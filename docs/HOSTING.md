# Размещение, домен и разделение доступа

## Рекомендуемый вариант

Для одного дома со студией и большим номером сейчас достаточно статического публичного сайта и перехода на Avito. Нет своей формы, базы, платежей и календаря, поэтому публичной части не нужен сервер Node.js. Это уменьшает стоимость сопровождения и поверхность атаки.

Первый кандидат — обычный виртуальный хостинг Timeweb с размещением в России: загрузка только `dist/`, собственный домен, HTTPS. На официальной странице заявлены SSL, резервные копии и тестовый период: https://timeweb.com/ru/services/hosting/ . Это выбор по простоте, **не гарантия доступности у каждого российского оператора**. Регион площадки, поддержку HTTP-заголовков, актуальный тариф и стоимость продления уточнить перед оплатой; конкретные цены здесь не обещаны.

Альтернатива — Yandex Object Storage для статики. Потребуются публичный бакет только с публичными файлами, домен и настройка HTTPS через Certificate Manager; настройка сложнее обычного хостинга, расходы зависят от хранения/запросов/трафика. Официальное описание: https://yandex.cloud/ru/docs/storage/concepts/hosting и инструкция HTTPS: https://yandex.cloud/ru/docs/tutorials/web/static/ . Backend и админку в бакет не загружать.

Render оставить действующим до успешной проверки новой площадки. Смена домена поверх прежнего Render сама по себе не устраняет сетевые ограничения к его инфраструктуре. Зарубежный CDN и иностранные шрифты/скрипты как обязательную зависимость не добавлять. Для любой площадки хранить независимую копию публичной сборки и резервную копию БД вне неё.

## Домен

В исходниках встречается `grantarkhyz.ru`, но владение, срок оплаты, DNS и фактическая работоспособность не подтверждены. Сначала проверить аккаунт регистратора и доступ владельца. Если домен принадлежит семье — сохранить его. Если нет — выбрать доступное имя в .ru и зарегистрировать на владельца, включить MFA и автопродление. Не регистрировать и не оплачивать без решения владельца.

Выбрать один основной HTTPS адрес и перенаправить www на него (или наоборот). Сгенерировать sitemap с этим адресом, добавить canonical и OG URL, обновить Яндекс Вебмастер/Google Search Console. Проверочные HTML-файлы сохранены, но их принадлежность аккаунтам нужно проверить. Не публиковать обе версии как разные страницы: `/index.html` и `/start-sales.html` после переноса можно перенаправить 301 на `/`.

## Публичный сайт и закрытая админка

```text
Гость → HTTPS основной домен → только dist/ → Avito
Владелец → HTTPS admin.<домен> → шлюз MFA/IP + rate limit
          → Node на loopback/в частной сети → закрытая PostgreSQL
```

Публичный хост не имеет DATABASE_URL и не проксирует административные адреса. У админки отдельное развёртывание, секреты окружения, no-store, HTTPS и проверка точного Origin. База не доступна из интернета; учётная запись с минимумом прав, проверяемые резервные копии. Закрытая админка не должна требовать VPN от гостей. Для семьи при отсутствии потребности в собственных заявках можно вообще не запускать админку и пользоваться Avito; старую БД сохранить для необходимых прежних заявок отдельно.

## Последовательность переноса без простоя

1. Сохранить текущий коммит/сборку и конфигурацию Render; отдельно сделать проверяемую резервную копию существующей БД. Не экспортировать персональные данные в GitHub.
2. Добавить реальные фотографии, разнести параметры по студии и большому номеру, подтвердить контакты/цены/условия. Просмотреть страницу владельцем.
3. Собрать `npm ci && npm test && npm run build:public`. Загрузить только `dist/` на временный адрес новой площадки. На ней запретить листинг папок; настроить nosniff, DENY/frame-ancestors, Referrer-Policy и CSP `default-src 'self'; style-src 'self'; img-src 'self' data:; object-src 'none'; base-uri 'self'; frame-ancestors 'none'`.
4. Проверить HTTPS, все прежние URL, телефонные размеры 360/390/768 px, клавиатуру, ссылки Avito, отсутствие сторонних ресурсов, исходников и административного API в сборке. Проверить из России **без VPN** хотя бы через мобильный интернет и домашнего оператора; записать результат и дату. Среда текущего аудита этого не заменяет.
5. После успешной проверки подготовить DNS (снизить TTL заранее, сохранить старые записи), переключить основной домен, обеспечить сертификат для apex/www. Render не удалять. Обновить canonical/sitemap/Вебмастер.
6. Контролировать сайт из двух российских сетей после переключения. При проблеме вернуть сохранённые DNS/предыдущую сборку. Изменение DNS не мгновенное: ждать TTL, не удалять старую площадку до стабилизации.
7. Только после стабильной работы и резервного копирования решать о завершении старого Render. Этот PR не меняет DNS, провайдеров, публичность репозитория или сервиса и не развёртывается автоматически.

Собственную форму бронирования добавлять отдельным проектным решением: точный состав заявки, согласие/политика и применимые требования к персональным данным, серверная проверка, антиспам, уведомления, сроки хранения, MFA админки и резервирование. Не имитировать подтверждённую бронь без календаря и ответа владельца.
